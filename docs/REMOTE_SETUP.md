# VPN bootstrap — запуск с локального компьютера

Главная команда: `bash bootstrap.sh --help`. Скрипт запускается на Mac/Linux
и подключается по SSH к указанному VPS. PR остаётся **черновым** до испытания
на реальном сервере, безопасного отката SSH и проверки клиентского REALITY.

## Что устанавливается

- `--protocol xray`: установить Xray VLESS/REALITY в отдельный Docker-контейнер
  `xray-reality`. Существующая AmneziaWG должна сохраниться без изменений.
- `--protocol amnezia`: только подготовить отдельного SSH-пользователя
  `amnezia` для **официального** клиента AmneziaVPN. Контейнер AmneziaWG
  ставится и управляется приложением, не этим скриптом.
- `--protocol both`: выполнить оба этапа.
- `vpnadmin` — независимый постоянный администратор, управляющий VPS с
  нескольких компьютеров. Пользователи `xray` и `amnezia` имеют отдельные
  учётные записи и SSH-ключи. Их `sudo NOPASSWD: ALL` даёт root-права и **не
  является строгой изоляцией** контейнеров.

## SSH-параметры главного скрипта

| Параметр | Объяснение |
| --- | --- |
| `--server` | IP/DNS-имя VPS |
| `--protocol` | `xray`, `amnezia` либо `both` |
| `--initial-ssh-user` | Пользователь **до установки**, обычно `root` |
| `--initial-ssh-private-key` | Необязательный путь к приватному ключу **существующего** SSH-пользователя. **Если не задан**, SSH использует агент либо предлагает пароль |
| `--server-ssh-port` | SSH-порт VPS (по умолчанию 22) |
| `--vpnadmin-ssh-private-key` | Приватный ключ, который SSH использует **локально** для проверки `vpnadmin` |
| `--vpnadmin-ssh-public-key` | Публичный ключ для `vpnadmin`, устанавливается на VPS |
| `--xray-ssh-private-key` | Локальный приватный ключ для проверки входа под `xray` |
| `--xray-ssh-public-key` | Публичный ключ, устанавливается пользователю `xray` |
| `--amnezia-ssh-private-key` | Локальный приватный ключ для проверки `amnezia` при её подготовке |
| `--amnezia-ssh-public-key` | Публичный ключ `amnezia` |
| `--confirm-disable-root-ssh` | Явное согласие **запретить вход root по SSH и по паролю, и по ключу** в конце успешной установки |

Пути по умолчанию для новых пользователей: `~/.ssh/vpnadmin`,
`~/.ssh/xray`, `~/.ssh/amnezia` и соответствующие `.pub`.
Приватные ключи **не копируются** на VPS и не отправляются в GitHub.
Старые названия параметров пока поддерживаются для обратной совместимости,
но не рекомендуются для новых команд.

## Пример для VPS, где root сейчас входит по паролю

До запуска: резервная копия VPS, доступ к консоли восстановления и
проверенная работа существующей AmneziaWG. Убедись, что AmneziaVPN управляет
сервером под `amnezia`, а не `root`.

```bash
bash bootstrap.sh \
  --server 194.87.17.214 \
  --protocol xray \
  --initial-ssh-user root \
  --vpnadmin-ssh-private-key "$HOME/.ssh/vpnadmin" \
  --vpnadmin-ssh-public-key "$HOME/.ssh/vpnadmin.pub" \
  --xray-ssh-private-key "$HOME/.ssh/xray" \
  --xray-ssh-public-key "$HOME/.ssh/xray.pub" \
  --confirm-disable-root-ssh
```

`--initial-ssh-private-key` здесь **не передаётся**, потому что первоначальный
root-SSH уже работает по паролю. Если исходный SSH-пользователь использует
ключ, можно добавить `--initial-ssh-private-key ~/.ssh/old_admin`.

Установка Xray принудительно использует `--no-firewall` и
`--skip-package-upgrade`, чтобы не менять правила существующей AmneziaWG.
Docker-демон не перезапускается, если он уже работает. Отсутствующий Compose
v2 устанавливается отдельно только когда APT-план не предусматривает
изменение Docker Engine/containerd.

**Примечание:** это выполнение реальных изменений на VPS. В ходе успешного
завершения `PermitRootLogin no` отключает root-SSH. Сначала скрипт должен
подтвердить новые SSH-сеансы `vpnadmin` и `xray`, а затем поставить защитный
таймер отката перед сменой sshd-конфигурации. Таймер и сам откат должны быть
проверены на тестовом VPS — статические GitHub Actions не подтверждают этот
сценарий.

## Несколько компьютеров

На другом компьютере создай **свою** пару SSH-ключей и передай только
публичный ключ доверенному Mac. После первой установки VPS добавь ключ:

```bash
bash bin/add-admin-key.sh VPS_IP ~/.ssh/vpnadmin /path/to/other_pc.pub 22
```

У всех компьютеров будет доступ через один VPS-аккаунт `vpnadmin` с
**разными** ключами. При потере устройства можно отозвать только его ключ.

`ssh-add ~/.ssh/vpnadmin ~/.ssh/xray` загружает локальные ключи в
`ssh-agent`; приватные ключи при этом остаются на компьютере.

## Проверка после установки

С Mac:

```bash
ssh -i ~/.ssh/vpnadmin vpnadmin@VPS_IP 'sudo vpn-status'
ssh -i ~/.ssh/vpnadmin vpnadmin@VPS_IP 'sudo vpn-add-user macos'
```

VLESS-ссылки и sing-box JSON — **секреты**. Не публикуй их в GitHub.
См. `clients/README.md` для выборочной маршрутизации: **DIRECT по умолчанию**;
через Xray только выбранные сайты и приложения.

Полный чек-лист для уже работающего AmneziaWG VPS:
`docs/EXISTING_AMNEZIA_RUNBOOK.md`.

## Дополнительно

Проверь актуальные обновления безопасности ядра Ubuntu и уязвимости MPTCP,
когда сервер общедоступен; не путай обновление ядра с обновлением Xray-контейнера.
Перезагрузка VPS может временно отключить оба VPN.
